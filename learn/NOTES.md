# Teaching Notes

Working notes on how this learner wants to be taught. Refer to these when designing lessons.

## Learner profile
- **New to Python.** Never assume language knowledge — introduce each construct the first time it appears, with a plain-English explanation.
- Wants to learn **algorithmic trading from scratch** (concepts first, not cargo-culting a bot).
- Targeting **crypto** markets.
- **Paper-trade and backtest first**; real money only later, once a strategy is validated.
- Wants to use **Claude Code** as the dev environment / pair programmer.

## Teaching preferences (update as discovered)
- Keep each lesson to a single tangible win; respect small working memory.
- Favor retrieval practice (quizzes, recall) over re-reading.
- Always tie lessons back to the mission and cite trusted sources.
- Lead with the mental model before any code.

## Safety stance
- Emphasize capital preservation and risk controls throughout.
- Never present a backtest result as a promise of future returns.
- Default every code example to paper/dry-run/testnet until the learner explicitly graduates to live trading with hard risk limits.

## Open questions to resolve later
- Which exchange/sandbox to target for the first simulated order.
- Whether the learner prefers hand-rolled scripts long-term or wants to adopt Freqtrade once fundamentals land.
